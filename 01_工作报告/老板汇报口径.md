# 老板汇报口径

## 汇报原则

给老板看的内容要少讲过程，多讲结果、经营价值、风险和需要拍板的事项。

张总按公司老板和经营决策者定位。形成汇报前，应先查阅 `11_张总分享专区` 中与当前主题直接相关的内容，再与当前业务数据、历史台账和项目进展交叉验证。

## 信息使用顺序

1. 当前任务的真实业务数据和已确认事实。
2. 张总最新且已确认的相关分享、经营要求和关注点。
3. 工作库中的历史台账、复盘和报告。
4. AI 分析判断，仅作为建议并明确标识。

不得使用不相关的分享内容套结论，也不得为了迎合分享内容而改变数据判断。

## 标准结构

1. 结论：建议老板关注什么、决策什么。
2. 数据结果：用数字说明进展、金额、周期、风险数量。
3. 经营价值：说明对毛利、成本、成交、交期、质量、现金流的影响。
4. 问题：说明问题、原因、影响。
5. 动作：说明下一步谁做、何时完成、产出什么。
6. 决策：列出可选方案、建议方案和不决策风险。

## 张总关注点转化规则

| 汇报内容 | 必须回答的问题 |
|---|---|
| 张总关注点 | 与本次汇报直接相关的分享或明确要求是什么？来源编号是什么？ |
| 数据验证 | 当前数据支持、部分支持还是不支持该判断？ |
| 经营影响 | 对毛利、收入、成本、交付、质量、库存、现金流和销售支持有什么影响？ |
| 建议动作 | 基于分享方向和数据结果，具体应该做什么？ |
| 决策事项 | 哪些需要张总拍板？有哪些选项和不决策风险？ |

建议在汇报中使用以下状态：

- `一致`：张总关注方向与数据结论一致。
- `部分一致`：方向一致，但数据不足或执行条件尚未满足。
- `存在差异`：分享判断与当前数据不一致，需要说明原因和决策选项。
- `待确认`：分享来源、原意、数据口径或适用范围未确认。

## 适合老板的表达方式

| 不建议 | 建议 |
|---|---|
| 本周跟进了很多供应商 | 本周完成 3 家供应商比价，初步有 1 个降本机会，金额待确认 |
| 包材还在推进 | 包材交期存在延期风险，若不切换备选供应商，预计影响上市节点 |
| 成本有所优化 | 按当前数量测算，预计优化金额为 X；若数量和税费未确认，标注待确认 |
| 供应商需要管理 | 建议将该供应商降为 C 类，同时启动备选供应商验证 |

## 必须避免

- 不带数据来源的金额。
- 没有建议的风险描述。
- 只讲过程，不讲对公司经营的影响。
- 把待确认事项写成已经确认。
- 只引用张总观点，不提供数据验证和经营建议。
- 把转述或 AI 推断写成张总原话或正式决定。
