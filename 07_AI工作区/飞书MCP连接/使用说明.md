第二期本地服务端白名单：

- 文档：`docx.v1.document.create`、`docx.v1.documentBlockChildren.create`
- 联系人解析与消息：`contact.v3.user.batchGetId`、`im.v1.message.create`。姓名查询工具未启用。

消息由应用机器人身份发送，不冒充当前用户。文档工具使用用户身份。两个服务都采用 `prompt` 审批模式；首次创建文档、写正文或发消息前，还必须由用户确认具体目标和内容。官方 `docx.v1.documentBlock.patch` 的当前参数包含删除表格行、列等操作，因此已从白名单移除并加入拒绝列表。

飞书侧最小新增权限：

- `im:message:send_as_bot`（应用身份）：允许机器人向应用可用范围内用户，以及机器人所在群发送消息；不申请消息读取、批量发送或群管理权限。
- `docx:document`（用户身份）：文档正文写入所必需。此合并权限也包含删除文档块内容的能力，但 MCP 服务端没有加载批量删除或文件删除工具。
- `base:table:read`（用户身份，后续验收追加）：仅用于从 Base 根链接列出数据表名称和 `table_id`；不授予记录新增、更新或删除权限。
- `contact:user.id:readonly`（应用身份，后续验收追加）：仅用于通过已知邮箱或手机号解析用户 `open_id`；服务端只开放 `contact.v3.user.batchGetId`，不开放通讯录新增、修改、删除或组织架构遍历工具。
- `contact:user.base:readonly`（已发布但当前方案不可用）：真实调用证明 `contact.v3.user.findByDepartment` 不接受该 scope；应用身份和用户身份均明确要求 `contact:contact.base:readonly` 等更宽通讯录权限。未经用户再次确认，不申请更宽权限；本机已移除姓名查询工具并从 OAuth scope 中撤下该权限。

还需在应用中启用“机器人”能力。新增权限生效前必须创建版本、提交审核并发布；“已提交”不等于“已生效”。

## 只读工具白名单

MCP 服务端只暴露以下 5 个工具：

- `docx.v1.document.rawContent`：读取新版云文档正文
- `wiki.v1.node.search`：搜索知识库节点
- `wiki.v2.space.getNode`：读取知识库节点信息
- `bitable.v1.appTable.list`：列出 Base 中的数据表名称和 ID，用于解析未包含 `table=tbl...` 的链接
- `bitable.v1.appTableRecord.search`：查询多维表格记录

未暴露消息发送、群组创建、文档创建/编辑/删除、多维表格新增/更新/删除等工具。Codex 项目配置同时设置了 `enabled_tools` 白名单和写入工具 `disabled_tools` 防线。

## 重新录入 App ID 与 App Secret

在 PowerShell 中运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Administrator\.codex\scripts\Initialize-FeishuMcpCredential.ps1" -Force
```

Windows PowerShell 的隐藏输入建议使用鼠标右键或 `Shift+Insert` 粘贴，不要使用 `Ctrl+V`。脚本会先调用飞书官方接口验证 App ID/App Secret，验证成功后才保存 DPAPI 文件，不输出 access token。

## 重新授权与撤销授权

重新登录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Administrator\.codex\scripts\Start-FeishuMcp.ps1" -Action Login
```

第二期权限发布生效后重新授权：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Administrator\.codex\scripts\Start-FeishuMcp.ps1" -Action LoginPhase2
```

本机官方 0.5.1 的 OAuth 等待时间已由 60 秒可回滚地调整为 300 秒，以避免 Windows 浏览器回调前监听提前关闭；原始文件备份保存在相邻目录，文件名带 `before-300s-timeout.bak`。

清除本地用户授权：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\Users\Administrator\.codex\scripts\Start-FeishuMcp.ps1" -Action Logout
```

完整撤销还应在飞书客户端的应用授权管理中撤销“Codex只读助手”，必要时在开放平台停用应用或移除权限。

## 启动、停止和状态检查

Codex 会按项目配置自动启动 STDIO MCP；不需要单独常驻运行。关闭 Codex 任务或停止 MCP 后，子进程会退出。

检查配置：

```powershell
codex mcp list
codex mcp get lark-mcp-readonly
codex mcp get lark-mcp-doc-write-controlled
codex mcp get lark-mcp-message-send-controlled
```

项目配置变更后应重启 Codex。重启后在 MCP 状态页或 `/mcp` 中确认 `lark-mcp-readonly` 已启动并仅显示上述 4 个工具。

## 更换验收资源

在 Codex 中提供以下任一资源，并明确要求“只读验收”：

- 飞书云文档链接；
- 飞书知识库节点链接；
- 飞书多维表格链接及表名（必要时补充 `table_id`）。

真实验收必须返回可人工核对的标题、字段或正文片段。在成功读取真实资源前，状态只能写“技术配置完成、登录成功，真实业务查询待验收”。

## 卸载

1. 先运行 `Logout` 并在飞书侧撤销应用授权。
2. 从项目配置中删除三个飞书 MCP 配置段。
3. 删除上述启动/初始化/验收脚本、DPAPI 凭据文件和官方组件目录。
4. 重启 Codex，并运行 `codex mcp list` 确认服务消失。

执行卸载前保留 `E:\新AI工具人\.codex\backups\` 中的配置备份，避免影响其他 MCP。
