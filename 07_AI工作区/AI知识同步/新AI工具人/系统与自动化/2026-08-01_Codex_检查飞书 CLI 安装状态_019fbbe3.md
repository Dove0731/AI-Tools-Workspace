## 推荐操作顺序

### 1. 安装全局 Node.js 和飞书 CLI

当前电脑没有系统级 `node`、`npm`，先安装 Node.js LTS，然后重新打开 PowerShell：

```powershell
winget install OpenJS.NodeJS.LTS
```

验证：

```powershell
node --version
npm --version
```

安装已验证过的飞书官方组件版本：

```powershell
npm install --global @larksuiteoapi/lark-mcp@0.5.1
```

验证：

```powershell
lark-mcp --version
lark-mcp --help
lark-mcp whoami
```

CLI 正式命令名是 `lark-mcp`，不是 `feishu` 或 `lark`。

### 2. 不要在命令行明文填写 App Secret

虽然 CLI 支持：

```powershell
lark-mcp login --app-id <AppID> --app-secret <AppSecret>
```

但这可能进入命令历史。建议继续使用你本机已有的 DPAPI 凭据和登录脚本：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File "C:\Users\Administrator\.codex\scripts\Start-FeishuMcp.ps1" `
  -Action Login
```

已有凭据文件：

```text
C:\Users\Administrator\.codex\credentials\feishu-mcp-credential.clixml
```

它仅供当前 Windows 用户解密，不应复制到工作区或 Git。

### 3. 把飞书 MCP 从项目级迁移到 Codex 用户级

目前飞书配置在：

```text
E:\新AI工具人\.codex\config.toml
```

需要将三个飞书配置段复制到：

```text
C:\Users\Administrator\.codex\config.toml
```

需要迁移的配置段：

```toml
[mcp_servers.lark-mcp-readonly]
[mcp_servers.lark-mcp-doc-write-controlled]
[mcp_servers.lark-mcp-message-send-controlled]
```

保持当前安全状态：

- `lark-mcp-readonly`：`enabled = true`
- `lark-mcp-doc-write-controlled`：`enabled = false`
- `lark-mcp-message-send-controlled`：`enabled = false`
- 写入和发消息继续使用 `default_tools_approval_mode = "prompt"`
- 保留现有 `enabled_tools`、`disabled_tools` 白名单

Codex 官方配置规则确认：用户级配置位于 `~/.codex/config.toml`，项目级配置位于项目内 `.codex/config.toml`；Windows 对应用户级路径就是上述文件。[Codex 配置参考](https://learn.chatgpt.com/docs/config-file/config-reference#configtoml)

迁移后先不要马上删除项目级配置，等全局配置验收通过后再清理重复段。

### 4. 重启 Codex 并验收

完全退出并重新启动 Codex，然后执行：

```powershell
codex mcp list
codex mcp get lark-mcp-readonly
codex mcp get lark-mcp-doc-write-controlled
codex mcp get lark-mcp-message-send-controlled
```

预期结果：

- 三个服务在任意目录下都能被列出
- 只读服务为 `enabled`
- 两个写入服务为 `disabled`
- 只读服务只显示文档、知识库、多维表格查询工具

最后提供一条真实飞书文档、知识库或多维表格链接，完成可人工核对的读取验收。配置成功、登录成功不等于真实业务资源已经验收。

### 5. 后续开启“操控”能力

如果“操控”不仅是读取，还包括创建文档或发送消息，需要另外完成：

- 飞书开放平台发布新增权限
- 启用机器人能力
- 重新执行第二期 OAuth：`LoginPhase2`
- 仅启用相应的受控 MCP
- 首次写入或发送前确认具体目标和内容
- 写入后只读反查留证

不建议一次性开放全部飞书 API，也不要开放批量发消息、删除文档、删除记录或群管理权限。
