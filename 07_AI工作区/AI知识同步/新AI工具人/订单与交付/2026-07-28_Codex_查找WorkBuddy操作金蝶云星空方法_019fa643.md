## 方式一：让 WorkBuddy 模拟人工操作

适合少量、低风险、重复性操作，例如：

- 登录金蝶云星空并查询采购订单
- 按供应商、日期、物料筛选
- 导出订单或库存报表
- 把导出的 Excel 汇总分析
- 生成采购异常清单

操作流程：

1. 在电脑安装并登录腾讯 WorkBuddy。
2. 打开金蝶云星空客户端或网页版，人工完成登录。
3. 在 WorkBuddy 新建任务，明确告诉它：
   - 操作哪个系统
   - 查询范围
   - 筛选条件
   - 输出位置
   - 哪些动作必须停下来确认
4. 首次执行时全程观察，不要直接设置定时任务。
5. 核对导出的订单数、金额、组织、日期范围和单据状态。

可直接复制这条指令：

> 请操作当前已登录的金蝶云星空，只进行查询和导出，不新增、不修改、不审核、不反审核、不删除单据。进入采购订单列表，筛选采购组织为【待填写】、单据日期为【待填写】、单据状态为【待填写】，导出全部明细到【指定文件夹】。完成后核对导出记录数、采购金额合计、供应商数量，并列出交期逾期、未交数量、异常单价和缺少交期的记录。任何字段含义不明确时暂停并询问我。

这种方式上线快，但容易受界面改版、弹窗、网络延迟和分辨率变化影响，不适合自动审核、付款、删除等高风险操作。

## 方式二：通过 MCP 接入金蝶云星空

这是更推荐的企业级方案。WorkBuddy官方支持通过 MCP 连接外部业务系统；配置后可以在对话中调用系统提供的查询或操作工具。[WorkBuddy MCP说明](https://www.workbuddy.ai/docs/zh/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)

```text

        ↓

        ↓
返回采购、库存、订单、供应商等数据
```

实施步骤：

接好以后，可以这样问：

| 测试账套 | 测试数据中心/账套ID |
| 接口方式 | WebAPI、OpenAPI或实施商自定义接口 |
| 认证方式 | 用户认证、AppID/AppSecret或其他方式 |
| 接口账号 | 专用只读接口账号 |
| 组织范围 | 接口账号能查询哪些采购、库存组织 |
| 网络要求 | 是否限制IP、内网、VPN或防火墙 |
| 接口文档 | 金蝶官方文档或实施商接口样例 |
| 测试单据 | 1—3张可人工核对的采购订单 |

金蝶支持GUI客户端和HTML5登录，但HTML5登录网址、认证方式和接口路径可能随部署方式不同，不能根据常见地址直接猜测。[金蝶云星空门户登录说明](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E9%97%A8%E6%88%B7%E7%99%BB)

# 三、在金蝶建立专用接口账号

由金蝶管理员操作。

## 3.1 创建专用用户

参考路径：

```text
系统管理
→ 系统管理
→ 用户管理
→ 新增
```

建议账号名称：

```text
AI_API_PURCHASE_READONLY
```

账号用途写清楚：

```text
仅供 Codex/MCP 查询采购、入库、库存、供应商和物料数据。
禁止新增、修改、审核、反审核、删除和付款。
```

金蝶用户会根据其角色和权限执行操作，因此必须使用独立账号并限制权限，不能直接使用 Administrator。[金蝶云星空用户管理说明](https://help.open.kingdee.com/dokuwiki_std/doku.php?id=%E7%94%A8%E6%88%B7)

## 3.2 建立只读角色

建议建立角色：

```text
AI采购数据查询员
```

只授予：

- 采购订单查看、列表查询；
- 采购收料单查看；
- 采购入库单查看；
- 即时库存查询；
- 供应商查看；
- 物料查看；
- 必要的报表查询。

明确取消：

- 新增；
- 修改；
- 删除；
- 提交；
- 撤销；
- 审核；
- 反审核；
- 作废；
- 付款；
- 数据引入；
- 批量更新。

## 3.3 设置组织和数据权限

不要只设置菜单权限，还要确认：

- 可以查询哪些采购组织；
- 可以查询哪些库存组织；
- 可以查询哪些仓库；
- 能否跨组织查询；
- 是否能看到采购价格；
- 是否能看到供应商结算信息；
- 是否能看到付款和应付信息。

建议第一期只开放一个测试组织。

## 3.4 准备接口认证资料

认证方式由金蝶版本和部署方式决定，常见可能包括：

- 账套ID；
- 用户名；
- 密码；
- 语言代码；
- AppID；
- AppSecret；
- 接口地址；
- Token或签名参数。

注意：

- 密码、AppSecret不要发在聊天中；
- 不要写入项目说明文档；
- 不要提交到代码仓库；
- 应放在本机环境变量或服务器密钥管理中；
- 正式账套与测试账套必须使用不同密钥。

# 四、定义需要查询的业务字段

开发前先让采购、IT、金蝶实施商确认字段，避免接口接通后口径不一致。

## 4.1 采购订单字段

第一期至少需要：

- 采购组织；
- 采购订单编号；
- 单据日期；
- 单据状态；
- 供应商编码；
- 供应商名称；
- 物料编码；
- 物料名称；
- 规格型号；
- 采购单位；
- 采购数量；
- 已收料数量；
- 已入库数量；
- 未交数量；
- 含税单价；
- 未税单价；
- 税率；
- 含税金额；
- 币别；
- 计划交货日期；
- 采购员；
- 关闭状态。

## 4.2 库存字段

至少需要：

- 库存组织；
- 仓库；
- 物料编码；
- 物料名称；
- 规格型号；
- 库存单位；
- 即时库存；
- 可用库存；
- 锁库数量；
- 批号；
- 生产日期；
- 有效期；
- 库存状态。

## 4.3 必须确认的口径

以下字段不能靠AI推断：

- 未交数量是“订单数量－入库数量”还是使用金蝶现有字段；
- 金额是含税还是未税；
- 采购单位与库存单位如何换算；
- 取消、作废、关闭订单是否纳入统计；
- 退料、退货是否冲减入库；
- 多币别如何汇总；
- 逾期天数使用计划交期还是确认交期；
- 供应商名称使用全称还是简称。

没有确认的统一标记“待确认”。

# 五、搭建金蝶 MCP 服务

这部分可以由IT、金蝶实施商完成，也可以交给 Codex在当前工作库中开发。

## 5.1 MCP服务需要做什么

它相当于一个安全中间层：

1. 接收 Codex传来的查询条件；
2. 检查调用的工具是否允许；
3. 检查组织、日期、单据状态是否合法；
4. 使用专用账号登录金蝶接口；
5. 调用金蝶查询接口；
6. 将金蝶字段转换为统一格式；
7. 隐藏密码、Token等敏感信息；
8. 将结果返回给 Codex；
9. 记录查询日志。

## 5.2 建议的工具设计

例如采购订单查询工具：

```json
{
  "tool": "query_purchase_orders",
  "inputs": {
    "purchase_org": "采购组织",
    "date_from": "2026-07-01",
    "date_to": "2026-07-31",
    "supplier_code": "",
    "material_code": "",
    "document_status": "",
    "only_open_orders": true,
    "page": 1,
    "page_size": 100
  }
}
```

返回格式：

```json
{
  "query_time": "2026-07-28 10:00:00",
  "purchase_org": "测试采购组织",
  "record_count": 1,
  "currency": "CNY",
  "records": [
    {
      "order_no": "PO000001",
      "supplier_code": "SUP001",
      "supplier_name": "示例供应商",
      "material_code": "MAT001",
      "purchase_qty": 10000,
      "received_qty": 6000,
      "unreceived_qty": 4000,
      "tax_price": 1.25,
      "tax_amount": 5000,
      "delivery_date": "2026-07-20",
      "status": "已审核"
    }
  ]
}
```

上面只是结构示意，不代表你们金蝶的真实字段和值。

## 5.3 密钥使用环境变量

建议使用类似名称：

```text
KINGDEE_BASE_URL
KINGDEE_ACCOUNT_ID
KINGDEE_API_USER
KINGDEE_API_PASSWORD
KINGDEE_APP_ID
KINGDEE_APP_SECRET
```

实际需要哪些变量，由认证方式决定。

## 5.4 加入安全控制

MCP层必须增加：

- 工具白名单；
- 组织白名单；
- 最大日期范围；
- 单次最大返回条数；
- 分页机制；
- 超时控制；
- 登录失败次数限制；
- 敏感字段脱敏；
- 调用日志；
- 接口异常提示；
- 禁止自定义SQL；
- 禁止用户传入任意接口地址。

# 六、在 Codex 中添加金蝶 MCP

Codex 官方支持本地 STDIO MCP服务和远程 Streamable HTTP MCP服务；桌面端、CLI和IDE可以共享MCP配置。[Codex MCP官方文档](https://developers.openai.com/codex/mcp)

## 方案A：Codex桌面界面添加

1. 打开 Codex。
2. 进入“设置”。
3. 找到“MCP servers”。
4. 点击“Add server”。
5. 名称填写：

```text
kingdee-galaxy
```

6. 选择连接方式：
   - MCP运行在当前电脑：选择 `STDIO`；
   - MCP部署在公司服务器：选择 `Streamable HTTP`。
7. 填写启动命令或MCP地址。
8. 保存。
9. 重启 Codex。
10. 在对话框输入：

```text
/mcp
```

11. 检查是否显示：

```text
kingdee-galaxy：Connected
```

官方流程同样要求添加后重启，并可通过 `/mcp` 查看连接状态。[Codex MCP连接步骤](https://developers.openai.com/codex/mcp)

## 方案B：本地 STDIO配置

适用于：

- 个人测试；
- MCP只在当前电脑运行；
- 金蝶只能从当前电脑或公司内网访问。

示例结构：

```toml
[mcp_servers.kingdee_galaxy]
command = "实际运行程序路径"
args = ["MCP服务启动参数"]
cwd = "MCP项目实际目录"
enabled = true
required = false
enabled_tools = [
  "test_connection",
  "query_purchase_orders",
  "query_purchase_receipts",
  "query_inventory",
  "query_suppliers",
  "query_materials"
]
default_tools_approval_mode = "prompt"
startup_timeout_sec = 30
tool_timeout_sec = 120
```

项目级配置文件可放在：

```text
E:\新AI工具人\.codex\config.toml
```

全局配置文件一般位于：

```text
C:\Users\Administrator\.codex\config.toml
```

建议先使用项目级配置，避免其他工作库自动获得金蝶访问能力。

## 方案C：远程 HTTP配置

适用于：

- 多人共同使用；
- MCP部署在公司服务器；
- 需要统一日志和权限；
- 需要IT集中管理密钥。

示例：

```toml
[mcp_servers.kingdee_galaxy]
url = "https://公司内部地址/mcp"
bearer_token_env_var = "KINGDEE_MCP_TOKEN"
enabled = true
required = false
enabled_tools = [
  "test_connection",
  "query_purchase_orders",
  "query_purchase_receipts",
  "query_inventory",
  "query_suppliers",
  "query_materials"
]
default_tools_approval_mode = "prompt"
tool_timeout_sec = 120
```

不要把真实Token直接写进 `config.toml`。

# 七、分级测试流程

不要连接成功后立即查询整个月或全账套。

## 第一级：MCP连接测试

对 Codex说：

> 调用 `test_connection` 测试金蝶云星空连接。只返回连接状态、测试账套名称、接口账号、允许查询的组织和可用工具。不要返回密码、Token或AppSecret，不执行任何业务查询。

验收：

- MCP状态正常；
- 返回的是测试账套；
- 接口账号正确；
- 组织权限正确；
- 没有暴露密钥。

## 第二级：单张订单测试

对 Codex说：

> 调用金蝶采购订单查询工具，只查询采购订单【填写订单号】。返回订单头、订单明细、数量、单位、含税单价、税率、金额、计划交期、入库数量和状态。不要修改任何数据。

人工进入金蝶核对：

- 订单编号；
- 明细行数；
- 供应商；
- 物料；
- 数量；
- 单位；
- 单价；
- 金额；
- 交期；
- 状态。

要求所有字段一致。

## 第三级：小范围列表测试

对 Codex说：

> 查询采购组织【填写】在2026年7月1日至2026年7月7日的采购订单，只返回前20条。按订单号和物料明细列示，并显示查询条件和总记录数。

验收：

- Codex记录数与金蝶列表一致；
- 筛选条件一致；
- 没有重复行；
- 分页正确；
- 关闭或作废单据口径一致。

## 第四级：采购与入库关联测试

对 Codex说：

> 查询采购订单【填写订单号】及其关联收料、入库记录，核对采购数量、累计收料数量、累计入库数量和未交数量。退料或退货单独列示，不要直接抵消。

验收重点：

```text
采购数量
→ 收料数量
→ 入库数量
→ 退料/退货
→ 未交数量
```

不能只看一个字段就宣称闭环。

## 第五级：异常和权限测试

必须主动测试：

- 查询无权限组织；
- 查询不存在的订单；
- 日期范围超过限制；
- 单次返回数量过大；
- 密码错误；
- 金蝶系统不可访问；
- MCP服务断开；
- 尝试调用禁止工具。

正确结果应是拒绝、提示原因并留下日志，而不是自动放宽权限。

# 八、正式使用时的指令写法

## 采购逾期查询

> 调用金蝶云星空只读工具，查询采购组织【填写】截至今天尚未完全入库的采购订单。按供应商、订单和物料列出采购数量、已入库数量、未交数量、含税单价、未交金额、计划交期和逾期天数。分别标记影响生产、影响客户交付和可能造成库存积压的订单。缺失字段标记“待确认”，只查询，不修改金蝶数据。

## 供应商交付分析

> 查询2026年1月1日至2026年6月30日的采购订单和入库记录，按供应商统计订单数、采购金额、按期交付数量、逾期数量和平均逾期天数。说明统计口径，退货和取消订单单独列示。不要仅根据价格判断供应商等级。

## 物料历史价格查询

> 查询物料编码【填写】过去12个月的采购记录，按供应商对比含税单价、未税单价、税率、采购数量、MOQ、交期和付款条件。币别、单位、运费或税率不一致时不要直接比较，单独标记“待确认”。

## 库存和在途联合分析

> 查询物料【填写】的即时库存、可用库存及未完全入库采购订单。按库存组织和仓库列示现有库存、在途数量、预计到货日期及合计可用量。单位换算口径不明确时不要合并。

# 九、正式上线控制

建议按以下节奏：

| 阶段 | 范围 | 上线条件 |
|---|---|---|
| 测试期 | 测试账套、单组织、只读 | 单据字段核对一致 |
| 试运行 | 正式账套、单组织、只读 | 连续1—2周无重大差异 |
| 扩展期 | 多组织、多模块查询 | 权限和口径验收完成 |
| 写入试点 | 新增草稿单据 | 单独审批、全量日志 |
| 高风险操作 | 审核、付款、删除 | 原则上不建议AI自动执行 |

即使以后开放写入，也建议：

- 新增单据只能保存为草稿；
- 提交前人工确认；
- 审核必须人工完成；
- 反审核、删除和付款禁止自动化；
- 每次写入保留调用人、原始指令、请求参数和金蝶返回结果。

# 十、常见故障排查

| 现象 | 可能原因 | 处理方式 |
|---|---|---|
| MCP显示未连接 | 启动命令或地址错误 | 检查服务地址并重启Codex |
| 金蝶登录失败 | 账套、账号或认证方式错误 | 停止反复尝试，联系管理员 |
| 能登录但查不到数据 | 组织或数据权限不足 | 检查角色和组织权限 |
| 返回字段为空 | 金蝶字段标识配置错误 | 根据表单元数据重新映射 |
| 金额对不上 | 含税/未税、币别口径不同 | 分口径核对 |
| 数量对不上 | 单位换算或退货未处理 | 核对采购单位、库存单位 |
| 查询很慢 | 日期过大或未分页 | 限制日期和分页 |
| 返回重复行 | 订单头与明细关联错误 | 按订单内码和明细内码去重 |
| 正式账套无法访问 | 内网、防火墙或IP白名单 | 由IT检查网络策略 |
| Codex看不到新工具 | 添加MCP后未重启 | 重启并输入 `/mcp` 检查 |

# 十一、最终验收清单

正式使用前，逐项确认：

- [ ] 使用专用接口账号；
- [ ] 账号不是 Administrator；
- [ ] 第一阶段只有查询权限；
- [ ] 使用测试账套完成验证；
- [ ] 采购订单记录数一致；
- [ ] 明细行数一致；
- [ ] 数量、单位一致；
- [ ] 含税/未税金额口径一致；
- [ ] 币别和税率一致；
- [ ] 入库、退货和未交口径一致；
- [ ] 组织权限验证完成；
- [ ] 大批量查询有分页；
- [ ] 密钥未写入代码或文档；
- [ ] 查询操作有日志；

- [ ] 正式账套上线已获得公司授权。

如果要由我直接开始搭建，下一步只需要先提供五项非敏感信息：金蝶版本、部署方式、测试系统地址、接口文档和第一期查询范围。账号密码与AppSecret暂时不用提供。
