# 每日经营复盘群运行 SOP V2.1

> 文件状态：当前执行版  
> 生效日期：2026-07-29  
> 适用范围：“每日经营复盘群”日常提交及Codex“每日简报”自动化  
> 管理依据：[《每日经营复盘群运行说明》](../../99_归档/原始资料归档/管理制度/2026/2026-07-29_每日经营复盘群运行说明原件/每日经营复盘群运行说明.docx)  
> 版本关系：替代V2.0作为群内日常默认格式；V2.0保留用于重大经营事项深度复盘。

## 1. 目的

让一线经营信息持续流动，训练主动观察、主动沟通、主动思考和主动行动。AI是辅助工具，不是每日提交的唯一内容或强制成果。

## 2. 角色责任

| 角色 | 责任 |
|---|---|
| 提交人 | 提供当天真实观察，核对AI初稿，提交本人能解释和承担的内容 |
| 管理者 | 鼓励先暴露问题、再共同校准；尽量提出判断和下一步方案 |
| 支持人/部门 | 对复盘中明确提出的支持需求作出回应或确认下一节点 |
| AI | 帮助提炼与表达，不编造事实，不替代责任、沟通或决策 |
| 群管理员/审核人 | 具体人员、提交时点和跟进方式待公司确认 |

## 3. 每日输入

当天可选择一类或多类真实内容：

- AI应用：使用了什么、解决了什么、遇到什么障碍；
- 经营发现：客户、产品、成本、交付、团队、流程、质量或风险的新发现；
- 问题暴露：最需要团队知道的问题或困难；
- 判断与建议：对问题的初步判断和处理建议；
- 下一步行动：准备验证或推动什么、需要谁支持。

## 4. 群内固定输出

【日期 / 姓名 / 部门】

1. 今天最重要的经营发现；
2. 我的初步判断；
3. 下一步准备怎么做；
4. 需要谁提供什么支持；
5. AI应用或启发（选填）。

除非存在重大风险需要升级，默认不扩写为10模块长报告。

## 5. 最低提交标准

没有成果或完整答案时，至少写清：

1. 今天观察到了什么；
2. 哪个原因暂不确定但值得关注；
3. 下一步准备如何验证；
4. 需要什么支持。

AI应用不作为合格提交的必填项。

## 6. 质量门槛

- 内容来自当天真实工作；
- 至少有经营观察，不能只罗列完成事项；
- 事实、判断和计划不混写；
- 不确定内容标“待确认”；
- 不写空话、套话和流水账；
- 管理者尽量形成判断和下一步方案；
- AI初稿经本人核验后才可提交。

## 7. 重要问题升级

重要问题必须及时沟通，不等待每日复盘。出现客户、收入、利润、质量、交付、库存、现金流、合规、品牌或重复性风险时：

1. 立即向有权限的负责人沟通；
2. 在群内按5项格式同步已知事实、初步判断、下一动作和所需支持；
3. 需要系统分析时，另启用[管理层每日经营复盘执行SOP V2.0](./管理层每日经营复盘执行SOP_V2.0.md)或对应专项异常SOP；
4. 未经确认不得把假设写成根因、把计划写成完成、把建议写成批准决定。

## 8. 提交流程

1. 提交人记录当天真实观察；
2. 可选择让AI帮助整理；
3. 本人核验并删改不符合实际的内容；
4. 重大问题先升级沟通；
5. 按5项模板提交群内；
6. 对明确支持需求和下一步节点继续跟进。

实际提交时间、群名称、审核人和归档要求，本次来源文件未明确，统一标“待确认”，不沿用未经重新确认的旧口径。
