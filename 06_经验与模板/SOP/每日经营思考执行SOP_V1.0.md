## 1. 目的

确保管理者每天不是汇报“做了什么”，而是完成一次可追踪的经营闭环：

**业务事实 → 经营影响 → 管理判断 → 解决方案 → 决策升级 → 组织沉淀 → 次日重点。**

## 2. 角色与责任

| 角色 | 核心责任 | 必须交付 | 责任类型 |
|---|---|---|---|
| 部门负责人 | 对经营判断、优先级和发布质量负责 | 审核后的每日经营思考；需要老板决策的明确选项 | A：最终负责 |
| 事项负责人 | 更新项目、订单、报价、异常和行动数据 | 可追溯事实、责任人、截止时间、最新状态 | R：执行负责 |
| 数据提供方 | 提供销售、财务、生产、品质等数据 | 来源文件、数据口径、统计截止时间 | R：数据负责 |
| AI 每日简报任务 | 汇总新增资料、检查缺口、生成七问草稿、写入台账 | 17:00 草稿；来源链接；待确认字段 | C：分析协助 |
| 提交人 | 复核事实并在群内发布 | 17:30 前发布；登记提交时间 | R：发布负责，姓名待确认 |
| 老板 | 只处理方向、资源、授权、跨部门协调或最终拍板 | 决策结论及约束条件 | A：决策负责 |

> 若同一人兼任多个角色，仍必须分别完成“数据确认、内容审核、发布登记”三个动作。

## 3. 每日输入清单

### 3.1 必查资料

每日只读取上次运行后新增或更新的资料，至少检查：

1. `09_产品开发管理/产品开发动作台账.md`
2. `10_采购与成本管理/采购成本动作台账.md`
3. `08_供应商管理`中的分级、评分、异常和合同账期资料
4. `05_问题反馈与复盘`中的新增异常及关闭状态
5. `02_会议与协同/协同事项总台账.md`
6. `04_数据台账/总台账.md`
7. 当天新增的报价、订单、会议纪要、客户反馈和复盘资料

### 3.2 最低事实字段

| 字段 | 最低要求 | 缺失时处理 |
|---|---|---|
| 事项对象 | 产品、物料、供应商、客户或项目名称 | 无法识别时不形成正式结论 |
| 事实 | 已发生的结果或风险事件 | 必须有来源；否则标注“待确认” |
| 统计时间 | 数据截止日期或事件发生日期 | 缺失则不得做趋势比较 |
| 经营影响 | 收入、毛利、成本、交付、质量、库存、现金流、客户或效率 | 无金额时可以定性，但必须说明缺口 |
| 责任人 | 唯一闭环负责人 | 无法确认时升级部门负责人 |
| 截止时间 | 明确到日期；P0明确到时间 | 不得使用“尽快、后续、持续跟进” |
| 来源 | 文件、台账、订单、邮件或会议纪要 | 无来源不得写成确定事实 |

## 4. 主题选择规则

每天只选一个主题。对候选事项按以下维度各打 0—5 分：

| 维度 | 0 分 | 5 分 |
|---|---|---|
| 收入/客户 | 无直接影响 | 已影响成交、交付或客户保留 |
| 毛利/成本 | 无明显影响 | 已造成大额损失或明确降本机会 |
| 交付/质量 | 无节点风险 | 已影响上市、订单或质量放行 |
| 库存/现金流 | 无占用风险 | 已形成明显积压、预付款或回款风险 |
| 紧急程度 | 可日常处理 | 当天必须决策或处置 |

**主题总分 = 五项得分之和。** 总分最高者作为当日主题；同分时按 `P0 > P1 > P2 > 待确认`，再按客户和现金影响排序。

以下事项不进入主题池：纯工作过程、没有经营影响的普通待办、只有观点而没有事实来源的内容。

## 5. 每日执行时间表

| 时间 | 执行动作 | 责任人 | 输出/验收 |
|---|---|---|---|
| 16:45 前 | 更新当天项目、订单、报价和异常资料 | 各事项负责人 | 台账有最新状态、来源、责任人、截止时间 |
| 16:45—17:00 | 检查数据口径和未关闭 P0/P1 | 部门负责人/数据提供方 | 冲突数据被标出，P0不等待日报 |
| 17:00—17:08 | AI读取新增资料并形成候选主题清单 | AI每日简报任务 | 候选主题、评分、来源链接 |
| 17:08—17:15 | 选定一个主题，区分事实/判断/待确认 | AI每日简报任务 | 数据完整性检查和主题结论 |
| 17:15—17:20 | 生成七问草稿并写入日报目录 | AI每日简报任务 | 七问全部有内容；不得编造 |
| 17:20—17:25 | 核对事实、责任人、时间、老板支持 | 提交人/部门负责人 | 通过发布前五项质量门禁 |
| 17:25—17:30 | 发布到《经营思考日报》群并登记台账 | 提交人 | 群内消息和提交时间；实际发送仍由人工完成 |
| 次日 09:30 前 | 检查昨日动作是否启动 | 事项负责人 | 台账更新为进行中/已完成/逾期 |

## 6. 七问输出标准

| 问题 | 必须包含 | 不合格表现 |
|---|---|---|
| 经营成果 | 已发生结果、经营价值、来源 | 只写“完成、推进、沟通” |
| 经营风险 | 风险事实、不处理的影响、时间窗口 | 只抱怨困难；没有影响判断 |
| 我的判断 | 问题本质、证据与假设边界 | 重复现象；把假设当事实 |
| 解决方案 | 动作、唯一责任人、截止时间、验收标准、残余风险 | “继续跟进、加强沟通” |
| 老板支持 | 决策事项、选项或授权、最晚时间 | 把资料整理或基础分析交给老板 |
| 组织资产 | 已形成的文件、版本和链接 | 只有名称，没有真实文件 |
| 明日重点 | 一件最影响经营结果的事 | 多项普通待办清单 |

## 7. 发布前五项质量门禁

提交人必须逐项确认，任一项不通过不得作为正式内容发布：

- [ ] **事实门禁：** 所有确定性表述均有来源，数据截止时间明确。
- [ ] **判断门禁：** 已区分事实、初步判断和待确认事项。
- [ ] **方案门禁：** 方案有唯一责任人、截止时间和验收标准。
- [ ] **决策门禁：** 老板支持具体；无支持需求时明确写“无”。
- [ ] **资产门禁：** 组织资产是真实文件并可通过链接打开。

## 8. 异常与升级机制

| 情形 | 处理要求 | 时限 |
|---|---|---|
| P0风险 | 立即通知部门负责人，不等待17:00简报；当天确定补救方案 | 发现后30分钟内升级 |
| 数据冲突 | 同时保留两个口径，写明来源和差异，不自行选择“好看”的数字 | 当天标记，次工作日明确责任人 |
| 关键字段缺失 | 允许形成风险提示，不允许形成确定金额或原因结论 | 在七问中列明待确认字段 |
| 无新增经营事实 | 不编造新结论；从未关闭P0/P1中选择进展最大的事项 | 仍按17:00生成 |
| AI任务未运行 | 提交人使用七问模板手工完成 | 17:15前启动备用流程 |
| 17:30前无法确认 | 发布“待确认版”并说明缺口、责任人、补齐时间 | 不得静默缺报 |
| 行动逾期 | 台账标记“逾期”，说明原因和新节点；P0/P1升级部门负责人 | 次日09:30前 |

## 9. 发布与归档

1. 群内只发布“可直接发群版”，详细分析保留在工作库。
2. 日报文件命名：`YYYY-MM-DD_每日经营思考_主题.md`。
3. 每次发布后更新[每日经营思考执行台账](../../01_工作报告/日报/每日经营思考执行台账.md)。
4. 已确认内容状态改为“已提交”；未确认内容保持“草稿/待确认”。
5. 每周五复核未关闭动作，不因生成新日报而覆盖旧问题。

## 10. 每周复盘机制

每周五由部门负责人用 15 分钟检查：

- 本周是否连续提交、是否按时；
- 哪些判断最终被证明正确或错误；
- 哪些方案已经产生收入、毛利、降本、交付或风险避免结果；
- 哪些“老板支持”长期没有关闭；
- 哪些经验已形成 SOP、模板、案例或检查表；
- 是否连续重复同一主题却没有行动进展。

复盘结论必须更新到执行台账，不另做无闭环汇报。

## 11. 试运行KPI与验收标准

| 指标 | 计算口径 | 7天试运行目标 |
|---|---|---:|
| 按时提交率 | 17:30前提交天数 / 应提交天数 | 100% |
| 七问完整率 | 七问完整条数 / 应提交条数 | 100% |
| 事实可追溯率 | 有来源的事实数 / 确定性事实数 | 100% |
| 方案闭环率 | 有责任人、截止时间、验收标准的方案数 / 方案总数 | 100% |
| P0及时升级率 | 30分钟内升级的P0数 / P0总数 | 100% |
| 组织资产有效率 | 可打开文件链接数 / 申报资产数 | 100% |
| 逾期透明率 | 已登记逾期动作数 / 实际逾期动作数 | 100% |

### 试运行通过条件

连续 7 个工作日同时满足以下条件，SOP 方可转为正式稳定版：

1. 不缺报、不晚报；
2. 不出现无来源的确定性数据；
3. 每条方案均可找到责任人和截止时间；
4. P0风险均在日报前完成升级；
5. 至少形成 1 个真实可复用组织资产；
6. 第 7 天完成一次周复盘并记录改版意见。

未通过时不得只修改文字，应根据失败项修改责任、时间或门禁机制，并升级版本为 V1.1。

## 12. 7天试运行安排

| 阶段 | 时间 | 重点 | 验收结果 |
|---|---|---|---|
| 启动 | 第1天 | 确认提交人、部门负责人、群和17:00触发 | 四项信息全部明确 |
| 格式稳定 | 第2—3天 | 七问齐全、来源可追溯、只选一个主题 | 无流水账、无编造 |
| 行动闭环 | 第4—5天 | 检查责任人、截止时间、验收标准和逾期 | 台账能追踪到状态 |
| 价值验证 | 第6天 | 检查是否形成经营结果或风险避免 | 至少1项结果可验证 |
| 周复盘 | 第7天 | 统计KPI、记录问题、决定是否升版 | 通过/不通过结论明确 |
