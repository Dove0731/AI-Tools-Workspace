# 采购数据分析执行SOP

任务编号：AI-20260810-003  
任务名称：采购数据分析执行流程建设  
适用模块：采购订单价格分析、降本识别、涨价风险和供应商变化分析

## 一、目的

建立从采购订单Excel接收、数据检查、分析计算、报告输出到确认归档的完整执行流程，确保分析数据可追溯、计算口径一致、经营影响明确、未经确认的AI结果不进入正式业务目录。

本SOP只定义业务执行流程，不包含程序代码。

## 二、关联规则

执行时依次使用：

1. [采购订单导入规范](./采购订单导入规范.md)
2. [采购数据分析字段说明](./采购数据分析字段说明.md)
3. [采购价格对比逻辑](./采购价格对比逻辑.md)
4. [采购价格分析流程](./采购价格分析流程.md)
5. [采购分析输出模板](./采购分析输出模板.md)
6. [采购降本分析模板](./采购降本分析模板.md)

## 三、总体流程

```text
采购订单Excel接收
→ 原始文件登记
→ 字段及数据质量检查
→ 可比口径确认
→ 采购金额、价格、降本、涨价和供应商分析
→ 采购经营分析报告文字稿
→ AI待确认输出
→ 人工复核
→ 正式报告归档
→ 索引、台账和行动项更新
```

## 四、第一步：数据接收

### 4.1 输入

- 采购订单Excel。
- 如有：历史采购订单、供应商报价、到货记录、质量记录、年度采购计划。
- 数据来源、导出时间、数据期间和提供人。

### 4.2 接收登记

| 登记项 | 要求 |
|---|---|
| 任务编号 | 使用本次分析任务编号 |
| 原始文件名 | 保留原文件名 |
| 数据期间 | 明确起止日期 |
| 数据来源 | 系统名称、导出路径或提供部门 |
| 接收时间 | YYYY-MM-DD HH:mm |
| 提供人 | 姓名或部门 |
| 文件版本 | 原始版、补充版、修订版 |
| 数据范围 | 订单数量、明细行数、供应商数等 |

### 4.3 原始数据存放

- 新接收且尚未完成分类、脱敏或校验的原始Excel进入 `97_待整理`。
- 待录入分析的文件优先放入 `97_待整理/待录入台账`。
- 涉及敏感信息时先进入 `97_待整理/待脱敏检查`。
- 原始文件不得覆盖、改名后冒充原件或直接写入计算结果。
- 补充文件和修订文件保留独立版本及来源说明。

### 4.4 阶段输出

- 原始数据接收记录。
- 数据来源及版本说明。
- 待处理文件路径。
- 已接收/缺失资料清单。

### 4.5 进入下一步条件

采购订单Excel可读取，数据期间、来源和版本可识别。无法确认来源或数据范围时暂停正式分析并列为“待确认”。

## 五、第二步：数据检查

### 5.1 字段完整性

按《采购订单导入规范》检查：

- 供应商。
- 物料编码。
- 物料名称。
- 规格型号。
- 采购日期。
- 采购数量。
- 采购单价。
- 历史采购价格。
- 交期。
- 付款方式。
- 备注。

同时建议检查订单号、订单行号、类别、计量单位、币种、税率、运费、MOQ、订单状态、年度预计采购量和数据来源。

### 5.2 重复数据

优先以“订单号＋订单行号”识别唯一记录；没有订单行号时，以“订单号＋物料编码＋规格型号＋采购数量＋采购单价”辅助判断。

重复记录不得直接删除，应标注：

- 完全重复。
- 疑似重复。
- 订单拆分。
- 分批交付。
- 退货或冲销。
- 待人工确认。

只有确认重复后才从分析口径中排除，原始数据保持不变。

### 5.3 异常价格

检查：

- 单价为空、为0、为负数或非数值。
- 历史价格为空或为0却要求计算变化率。
- 当前价格超出历史可比价格范围。
- 价格变化达到已确认预警阈值。
- 同物料不同供应商同口径价格差异显著。
- 单位、币种、税费、运费或规格差异造成的假性涨跌。
- 小数点、数量级或录入错误。

建议5%关注、10%重点异常均属于待确认初始阈值，业务负责人确认前只展示事实变化。

### 5.4 单位一致性

检查并统一：

- 采购数量计量单位。
- 价格单位，例如元/kg、元/个、元/套。
- 规格换算关系。
- 币种及汇率日期。
- 含税/未税和税率。
- 含运费/不含运费。
- 数量梯度与MOQ。

无法可靠换算时标注“不可比”，不得强行比较。

### 5.5 特殊记录

以下记录单独分类，不直接进入正式采购金额和价格比较：

- 计划订单。
- 取消订单。
- 赠品或样品。
- 退货、冲销和负数记录。
- 待核销记录。
- 忽略价格或测试价格。
- 无法确认状态的记录。

### 5.6 数据检查报告

| 检查项 | 总数 | 有效 | 预警 | 阻断 | 待确认 |
|---|---:|---:|---:|---:|---:|
| 字段完整性 |  |  |  |  |  |
| 重复数据 |  |  |  |  |  |
| 异常价格 |  |  |  |  |  |
| 单位一致性 |  |  |  |  |  |
| 特殊记录 |  |  |  |  |  |

### 5.7 进入下一步条件

- 核心字段可支持采购金额计算。
- 当前价和历史价具备可比口径，或不可比记录已单独标识。
- 重复、异常和特殊记录已分类。
- 重大数据缺口已说明对结论的影响。

存在阻断项时，只能输出数据质量检查结果，不得生成确定的降本、涨价或供应商结论。

## 六、第三步：数据分析

### 6.1 采购金额

`采购金额 = 采购数量 × 采购单价`

汇总维度包括：

- 总采购金额。
- 按类别、物料、供应商和期间汇总。
- 采购金额前十物料和前十供应商。
- 采购集中度及单一供应风险。

采购金额变化应区分价格、数量、物料结构、税费和物流影响。

### 6.2 价格变化

- 单位价格变化：`当前价格－历史可比价格`
- 价格变化率：`（当前价格－历史可比价格）÷历史可比价格×100%`

分别输出上涨、下降、持平、不可比和数据不足记录。历史价格缺失或为0时不得计算变化率。

### 6.3 降本金额

- 单位节约：`历史可比价格－当前价格`
- 单项节约金额：`MAX（历史价格－当前价格，0）×当前采购数量`
- 年度预计节约金额：`MAX（历史价格－当前价格，0）×已确认年度预计采购量`

未提供经确认的年度采购量时，不得自动年化。节约金额还需检查税费、物流、损耗、MOQ、账期和一次性投入，必要时计算净经营收益。

### 6.4 涨价金额

- 单位涨价：`当前价格－历史价格`
- 涨价金额：`MAX（当前价格－历史价格，0）×当前采购数量`
- 年度预计增本：`MAX（当前价格－历史价格，0）×已确认年度预计采购量`

节约金额和涨价金额必须分开披露，并输出净价格影响，避免汇总净额掩盖重点涨价风险。

### 6.5 供应商变化

分析：

- 本期采购金额和占比。
- 报价变化及价格竞争力。
- 涨价物料和降价物料。
- 供应商新增、退出或份额变化。
- 交期、质量、MOQ和付款条件变化。
- 单一供应、断供和替代供应商情况。
- 谈价、锁价、分单、替代和账期优化机会。

供应商判断必须有报价、订单、交付、质量或风险记录支撑；不能只按低价评价。

### 6.6 阶段输出

- 采购金额汇总及明细。
- 价格上涨、下降和异常清单。
- 已实现节约及年度预计节约。
- 涨价增本及年度预计增本。
- 供应商变化和供应风险清单。
- 数据缺口及待确认事项。

## 七、第四步：输出报告

### 7.1 报告名称

`YYYY-MM-DD_采购经营分析报告.md`

报告先生成文字稿供用户确认；如需要落盘但尚未确认，进入AI输出暂存区，不得作为正式业务资料。

### 7.2 报告结构

#### 1. 本期采购金额

- 总采购金额及数据口径。
- 类别、物料和供应商结构。
- 与可比期间的变化及原因。
- 采购集中度和现金流影响。

#### 2. 降本成果

- 已实现节约金额。
- 年度预计节约金额。
- 净经营收益。
- 对毛利的影响。
- 可复制的降本机会。

#### 3. 涨价影响

- 涨价物料数和涨价金额。
- 年度预计增本。
- 重点异常物料及供应商。
- 涨价原因和毛利风险。

#### 4. 供应风险

- 单一供应与替代能力。
- 交期、质量和产能风险。
- MOQ、库存和现金流风险。
- 供应商价格竞争力与合作建议。

#### 5. 下一步动作

| 优先级 | 问题/机会 | 动作 | 经营价值 | 责任人 | 截止日期 | 状态 |
|---|---|---|---|---|---|---|
| P0/P1/P2 |  |  |  |  |  | 待处理 |

### 7.3 老板摘要

结论先行，至少说明：

1. 做出了什么采购和降本结果。
2. 节约或增本金额及毛利影响。
3. 避免或暴露了什么供应风险。
4. 支撑了什么交付、上市或销售事项。
5. 下一步如何优化。
6. 哪些事项需要老板决策。

### 7.4 报告复核

复核：

- 数据来源和期间。
- 价格可比口径。
- 计算公式和汇总结果。
- 节约与涨价是否分开。
- 年度预计量是否有依据。
- 供应商结论是否有事实支撑。
- 待确认事项是否明确。
- 正式报告是否经过用户确认。

## 八、第五步：归档规则

### 8.1 原始数据

存放位置：`97_待整理`

- 待录入分析：`97_待整理/待录入台账`。
- 待脱敏：`97_待整理/待脱敏检查`。
- 待确认来源或分类：`97_待整理/待人工确认` 或 `97_待整理/待分类`。
- 保留原始文件名、来源、接收时间和哈希/版本信息（如适用）。
- 不删除、不覆盖原始文件。

### 8.2 AI输出

存放位置：`98_AI输出暂存区`

- 未确认报告：`98_AI输出暂存区/待确认输出`。
- 已确认但尚未正式归档：`98_AI输出暂存区/已确认待入库`。
- 作废输出：进入作废目录并保留作废原因，不冒充正式版本。

### 8.3 确认后的正式成果

存放位置：`10_采购与成本管理`

建议按内容归档：

- 采购分析报告：`10_采购与成本管理/采购分析`。
- 订单执行分析：`10_采购与成本管理/采购订单`。
- 正式降本项目：`10_采购与成本管理/成本优化`。
- 报价比价结果：`10_采购与成本管理/报价比价`。

确认后同步：

- `10_采购与成本管理/采购与成本管理索引.md`。
- 对应采购订单、报价、降本或供应商台账。
- 必要时同步问题复盘和行动清单。
- Codex执行日志及任务状态。

## 九、完成标准

全部满足后任务方可标记完成：

- 原始数据来源和版本可追溯。
- 数据检查已完成，阻断项已处理或明确披露。
- 采购金额、价格、节约和涨价计算口径一致。
- 供应商变化与供应风险有事实依据。
- 采购经营分析报告包含五项规定内容。
- 数据缺口和待确认事项已列明。
- AI输出经过用户确认后才进入正式目录。
- 索引、台账、行动项和执行日志已按需更新。
