# 团队第二大脑互通架构

## 一、结论

本工作库以 `E:\新AI工具人` 为唯一的本地文件事实源。Obsidian 和 Codex 共同读写该目录，Git 记录版本，GitHub 私有仓库用于受控共享。GitHub 仓库创建、首次推送、团队加入和正式验收是四个不同状态，不得混写。

## 二、工具分工

| 工具 | 核心职责 | 输入 | 输出 | 不承担的职责 |
|---|---|---|---|---|
| GPT | 推理、归纳、判断和内容生成 | 用户目标、上下文、业务资料 | 分析草稿、建议、结构化内容 | 不直接承担文件同步和业务验收 |
| Codex | 读取规则和资料、修改文件、运行检查、生成差异 | `AGENTS.md`、工作库文件、用户任务 | Markdown、台账、报告、Git 差异和验证结果 | 不替代人工确认，不擅自上传敏感资料 |
| Obsidian | 人工阅读、链接、编辑和知识导航 | 本地 Markdown 和附件 | 已人工检查的笔记、链接和结构 | 不等同于版本备份或审批系统 |
| Git | 本地版本记录、分支、差异和恢复 | 本地文件变更 | Commit、Branch、Diff | 不负责成员权限和远程共享 |
| GitHub | 私有远程仓库、成员权限、Pull Request 和审核记录 | 已提交的 Git 版本 | 远程版本、审核记录和协作入口 | 不是实时共同编辑工具，也不是唯一备份 |

## 三、数据流

1. 人工将原始事实和业务资料写入工作库。
2. Codex 读取 `AGENTS.md` 和相关文件，形成分析、台账、SOP 或报告。
3. 未确认输出进入 `98_AI输出暂存区`，并明确标注“待确认”。
4. 人工在 Obsidian 中核对来源、口径、结论和链接。
5. Git 显示具体修改并形成可追溯提交。
6. 通过分支和 Pull Request 完成复核后，推送或合并到 GitHub 私有仓库。
7. 其他成员拉取最新 `main` 后继续工作。

## 四、责任边界

| 事项 | 责任人 | 验收证据 | 异常处理 |
|---|---|---|---|
| 原始资料真实性 | 资料提供人 | 原件、来源、日期 | 缺失时标“待确认” |
| AI 输出准确性 | 任务提交人/复核人 | 人工核对记录 | 不得直接转正式资料 |
| 文件结构和链接 | 文件维护人 | 链接检查、索引同步 | 发现断链及时修复 |
| Git 提交质量 | 提交人 | Diff、Commit 信息 | 拆分或撤回未合格变更 |
| 合并审核 | 仓库审核人 | Pull Request 审核记录 | 高风险变更不得自行合并 |
| 仓库权限 | 仓库管理员 | 权限台账和 GitHub 设置 | 立即回收异常权限 |
| 备份恢复 | 待确认 | 备份记录和恢复演练 | 未建立前不得宣称已闭环 |

## 五、状态定义

| 状态 | 完成条件 |
|---|---|
| 本地文件已创建 | 文件存在且通过 UTF-8、路径和内容检查 |
| Git 已初始化 | `git rev-parse` 可验证，默认分支为 `main` |
| 本地已提交 | 存在可核对的本地 Commit 哈希 |
| GitHub 仓库已创建 | 可反查仓库存在且为 Private |
| 已首次推送 | 本地与远程 `main` 的提交哈希一致 |
| 团队成员已加入 | GitHub 成员权限可反查并登记台账 |
| 团队已试运行 | 至少完成一次拉取、分支、提交、PR、合并和再次拉取 |
| 已正式验收 | 责任人、权限、备份、恢复、冲突和安全流程均有验收证据 |

## 六、安全边界

- 密码、令牌、密钥、凭据、`.env` 和加密凭据文件不得进入 Git。
- 采购底价、成本、配方、客户、付款和原始订单资料即使进入 Private 仓库，也必须经过上传范围确认和成员最小权限控制。
- GitHub 同步不能替代独立备份；备份责任人、频率、保留周期和恢复演练均为“待确认”。
- 不同时启用多套双向同步机制；如后续启用 Obsidian Sync 或其他云盘，必须先评估冲突风险。
