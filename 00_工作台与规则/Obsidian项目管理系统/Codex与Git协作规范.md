# Codex 与 Git 协作规范

## Codex 执行闭环

1. 明确目标、输入文件、允许修改范围、禁止事项和验收标准。
2. Codex 先检查事实来源和 Git 状态，再执行可逆的本地操作。
3. 新生成且未确认的业务判断放入 `98_AI输出暂存区`。
4. 在 [[07_AI工作区/Codex任务/README]] 记录变更文件、验证结果和待确认事项。
5. 人工确认数据和口径后，再同步正式台账、报告或知识文档。

## Git 安全流程

```powershell
git status --short
git diff --check
git diff --stat
git diff
```

确认范围和敏感信息后，才进入暂存、提交或推送。建议提交信息：

```text
docs(project): 建立项目管理模板与驾驶舱
```

## 必须暂停确认的事项

- Git 身份、远程仓库归属、认证、首次提交或首次推送。
- 凭证、合同底价、完整配方、客户机密或受限归档的上传范围。
- 外部发送、审批、发布、生产系统写入和真实业务验收。

Git 提交只证明文件版本已记录，不代表资料已发送、流程已批准或业务已闭环。
