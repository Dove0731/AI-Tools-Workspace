# Obsidian 项目管理系统

## 系统目标

本系统以当前工作库为唯一事实源，用 Obsidian 管理知识与项目，用 Codex 辅助整理、分析和执行，用 Git 记录可追溯变更。它不替代业务确认、审批、发送或系统上线。

## 四个核心入口

| 场景 | 入口 | 使用结果 |
|---|---|---|
| 今天先做什么 | [[00_工作台与规则/工作台]] | 聚焦 P0/P1、卡点和老板决策事项 |
| 管理全部项目 | [[03_项目管理/00_项目驾驶舱]] | 查看项目组合、风险、里程碑和待办 |
| 新建标准项目 | [[06_经验与模板/Obsidian项目管理模板/项目卡模板]] | 创建带统一属性和闭环结构的项目页 |
| 让 Codex 执行 | [[07_AI工作区/Codex任务/README]] | 留存任务边界、证据、变更与验收结果 |

## 推荐工作流

1. 新事项先进入 [[00_工作台与规则/工作台]]，信息不足标记“待确认”。
2. 确认要投入资源后，复制“项目卡模板”到 `03_项目管理/项目库/01_待启动`。
3. 启动后移动到 `02_进行中`，每个项目必须有负责人、下一步动作和截止日期。
4. 会议、决策、风险分别使用对应模板，并双向链接项目页。
5. Codex 产出先进入 `98_AI输出暂存区`；事实和口径确认后再入正式目录。
6. 重要变更先看 `git diff`，确认不含凭证和敏感资料后再提交。提交与推送不代表业务验收。
7. 项目完成后先复盘，再移入 `04_已完成`；符合归档条件后移入 `05_已归档` 或 `99_归档`。
